# doc-extractor: agent guide

Local-first PDF/CSV extraction library + CLI (`doc-extractor`). Every value keeps its source
location and the input's SHA-256; values are never silently rewritten. Python ≥ 3.10, MIT.

## Environment and commands

- Conda env `doc-extractor` (`environment.yml`). The base `python` has no pytest. Use
  `source ~/miniconda3/etc/profile.d/conda.sh && conda activate doc-extractor`, or call
  `~/miniconda3/envs/doc-extractor/bin/python` directly.
- Install: `pip install -e '.[all,dev,docs]'`
- Tests (CI gate, must stay at 100% statement + branch coverage):
  `python -m pytest -q --cov=doc_extractor --cov-branch --cov-fail-under=100`
- Format + lint (CI `check` job, must pass): `ruff format --check . && ruff check .`. Fix with
  `ruff format . && ruff check --fix .`. Ruff replaces black + isort (rule `I`) + linters;
  config in `pyproject.toml`, version pinned `>=0.17,<0.18`. Whole repo is clean.
- CI: `.github/workflows/ci.yml` (FINAM-style): `check` → `test` (OS × Python matrix, 100%
  coverage) / `docs` (`make -C docs html`) / `build` (wheel + twine check). Optional local
  hooks: `.pre-commit-config.yaml`.
- Docs: `make -C docs html` (Sphinx, warnings are errors) → `docs/_build/html/index.html`.
  Local only, not hosted.
- Example data: `python examples/make_demo_data.py` (deterministic). Add `--results` to
  refresh every `examples/*/results/` file after an intended output change, then review
  the diff.
- Visual check of any PDF:
  `python examples/07_compare_with_source/compare_with_source.py <pdf> [--profile-file Y]`,
  which writes `docs/private/output/<name>/report.html` (git-ignored).
- In zsh, an unquoted `$VAR` is not word-split; use `${=VAR}` when passing file lists.

## Layout

- `src/doc_extractor/api.py`: `extract()` / `inspect_file()` (NumPy docstrings feed the API
  docs). `cli.py`: argparse CLI. Its help text is user documentation; the top-level `--help`
  appends every subcommand's usage, generated from the parser.
- `readers/pdf_reader.py` (pdfplumber), `readers/csv_reader.py` (stdlib csv).
- `profiles/loader.py`: YAML allowlists (ops, params, encodings, date formats);
  `matching.py`: `required_text` / `required_headers`; `operations.py`: `table.map_columns`
  plus date/decimal normalization.
- `exporters/writer.py`: json/markdown/text/parquet/arrow. Parquet/Arrow record exports
  contain raw columns plus `<field>_normalized` columns (`RecordSet.to_polars(include_normalized=True)`).
- `presets/*.yaml`: six bundled generic presets.
- Real bank profiles live in `private/profiles/` (git-ignored), never in `src/` or `examples/`.
- `examples/NN_name/`: FINAM-style self-contained examples (`README.md`, `data/`, profile
  YAML, scripts, `results/`). `examples/expected_results.py` lists each documented command
  and its results file; `tests/test_examples.py` runs them all.
  `docs/design/bank-profiles/` are non-runnable design sketches for real banks.
- `docs/source/`: Sphinx + MyST Markdown, pydata theme. Sections: getting-started,
  user-guide, examples (each page `{include}`s the example README), reference
  (`cli.md` uses help text regenerated by `conf.py` into `_generated/`; `api.md` uses autodoc),
  development, about (includes CHANGELOG/SECURITY/AUDIT/LICENSE).
- Tests build their own fixtures (`tests/conftest.py`); many reference
  `examples/01_quickstart/payback_activity_csv.yaml`, so keep that path.

## Rules

- **Privacy:** real documents live only in `docs/private/`, `private/` or `.private/` (all
  git-ignored, and excluded from the docs build). Never copy their content, names, IBANs
  or amounts into tracked files, tests, examples or docs. Outputs and reports made from
  them stay in those folders.
- **Don't commit** unless the user explicitly asks.
- Raw values must stay raw. Normalized decimals are **strings** (`"-850.00"`); consumers cast
  with `Decimal` / `pl.Decimal`. Never introduce float parsing.
- Profiles are configuration, not code: new YAML keys must go through the allowlists in
  `profiles/loader.py` and `pdf_reader.validate_table_settings`.
- Keep the CLI help, `docs/source/user-guide/` and `README.md` consistent when behaviour
  changes. Example output changes must be refreshed with `make_demo_data.py --results`.
- Test fakes for optional backends: when a test injects a fake module into `sys.modules`
  (e.g. `pyarrow`), stub every real package that would import it as well (e.g. `pandas`).
  Otherwise the real package loads against the fake and crashes, depending on test order.

## Findings (2026-11-04)

- **All `--mode` × `--to` combinations were tested** (PDF with/without profile, CSV with
  profile). There are no crashes; refusals are deliberate (`content` + parquet/arrow,
  `tables`/`records` + text, `content` on CSV) and exit `2` with a hint. Matrix:
  `docs/source/user-guide/concepts.md`.
- **Ruled tables work well.** `examples/03_bank_statement_pdf` maps 20 transactions (one
  record set per page because the header repeats); `reconcile.py` checks
  opening + transactions = closing and every running balance.
- **Borderless detection is unreliable.** pdfplumber's `text` strategy cuts words when
  columns mix left- and right-aligned text and pulls in surrounding page text. No allowed
  setting combination fixes it (`examples/06_borderless_invoice`).
- **Real bank statements in `docs/private/` don't extract cleanly with generic presets:**
  - Santander: the ruled grid is found, but each transaction spans several lines inside one
    large cell, so cells come back mostly empty or merged.
  - Revolut: borderless, horizontal rules only; the borderless preset gives 15+ columns of
    word fragments; the ruled preset finds nothing.
  - Bancolombia: vertical column rules but no row rules; no table is found with any
    allowed setting.
- **Done: `pdf.table_from_header`** (`readers/header_table.py`): header row found by names,
  boundaries in the widest empty gap between columns (or `columns_x`), continuation lines via
  `new_row_column`, `end_before_text`. Plus `year_from_period` for `DD/MM` dates and decimals
  without leading zero. Lesson: with few rows, word spaces look like column gaps, hence the
  widest-gap rule (regression test in `tests/test_header_table.py`).
- **Bancolombia works:** `private/profiles/bancolombia_statement_pdf.yaml` (git-ignored) gives
  90 transactions on the private sample; `examples/08_statement_without_lines/check_statement.py
  <pdf> <profile>` reconciles every row and all summary totals. Next: Revolut, Santander.
- Fixed: Markdown tables lacked the `| --- |` row; record Parquet/Arrow exports lacked
  normalized values; the `--to text` error now names alternatives.
